# Security policy

## Scope

Report vulnerabilities that could expose contributor identities, unpublished submissions, moderation tools, database credentials, or permit unauthorized changes to records.

Do not include exploit details, tokens, personal data, or live endpoints in a public issue. Before public launch, the project must publish a monitored private disclosure address and a response-time commitment.

## Incident response

Personal-data breaches are handled per the draft breach procedure in [docs/BREACH_PROCEDURE.md](docs/BREACH_PROCEDURE.md) (GDPR arts. 33-34): roles, triage, containment, 72-hour supervisory-authority notification, data-subject notification, and the internal breach register. The monitored disclosure address and response-time commitment become operational at launch.

## Current prototype

This local prototype is not intended to store real reports or to be exposed on the public internet. Do not treat it as a production service.
